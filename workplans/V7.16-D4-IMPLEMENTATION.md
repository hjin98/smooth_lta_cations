# v7.16 D3→D4 implementation workplan

This is cycle coordination, not authority. The authorities are D1
`doc/specs/v7_16_molten_salt_occlusion_extension.md` r7, D2
`doc/specs/v7_16_cage_salt_numerical_method.md` r2, and D3
`doc/archs/lta_cation_generator_architecture.md`, section "v7.16
architecture delta".

## Frozen cycle decisions

- The module split, data flow and public interface in the D3 delta.
- Golden byte-identity fixtures are captured **before** any code change,
  for:
  - the dry path: Na-A seeds 0/1/2, CIF, POSCAR and LAMMPS;
  - the v7.15 sparse path: alpha 2 and beta 2 with counterions, seeds 0/1,
    on the population and smoothing entry points.
- After the change, the sparse path is run with
  `--occlusion-model sparse-v715` and must match its fixtures byte for byte.

## Stages (each ends green on the full suite)

1. **S0 fixtures.** Capture the golden fixtures; tests reference them.
2. **S1 data module.** Write `lta_cage_salt_data.py` and its regeneration,
   with a test comparing the regenerated module with the committed one and
   checking the CSV SHA-256s.
3. **S2 domain module.**
   - request parsing and validation;
   - window table and charge;
   - rebalancing, plus brute-force oracle 4;
   - V_eff, plus oracle 1 (V/4 at d = 0, the scale identity, α₀ = α₁);
   - floors;
   - verification, plus oracle 3 (manufactured cases);
   - record and sidecar.
4. **S3 build module.** Objective and gradient (finite-difference gradient
   test), insertion, continuation and polish, relocation, restarts, and
   per-start streams.
5. **S4 integration.**
   - selector, legacy-flag rejection, `finalize_cage_salt`, assembly,
     CLI flags, salt.json, failure path, and `--attempt-seed`;
   - tests: legacy and dry golden identity; oracle 5 (step-3 snapshot);
     oracle 6 (determinism); oracle 7 (precondition);
   - oracle 2: an independent verifier on re-parsed CIF, POSCAR and LAMMPS
     files, using a non-snapping reader and the sidecar.
6. **S5 documentation.** README, CHANGELOG, module spec notes and version
   7.16.0.
7. **S6 qualification.** Run the S-12 census (90 requests) with
   `validation/v716_s12_census.py`, writing a record under
   `qualification/v716/`, with stack versions. Apply the S-12 decision rule.
   Mark D3 current after its review. Render PDFs where a LaTeX engine is
   available; otherwise record that they are deferred.

## Acceptance

- The full suite passes.
- Golden identity holds.
- Oracles 1-7 pass.
- The census decision is recorded.
- The CLI runs end to end on the fixture.
- An independent D4 review finds no blocker.

## Non-goals

- Maximum-symmetry or unique-batch support with salt.
- Non-Al24 frameworks.
- Trivalent ions.
- Changes to D1 or D2. A defect found in them is routed to its owner.
