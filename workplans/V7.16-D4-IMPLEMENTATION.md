# v7.16 D3→D4 implementation workplan (r3)

This is cycle coordination, not authority. The authorities are D1 r7, D2
r2, and the D3 "v7.16 architecture delta" r3 in
`doc/archs/lta_cation_generator_architecture.md`.

**Gate.** No D4 code change happens before the D3 r3 delta check passes and
D3 is marked current.

## Record of early work

Three golden captures ran before D3 acceptance:
- S0a in commit `949f4fe`;
- S0b in commit `1d981c8`, 39 cases;
- the S0b addendum (41 cases: smoothing maximum symmetry and dry
  `--write-candidate`), committed with D3 r2.

They only capture outputs of unchanged v7.15.0 code, with stack versions in
the manifest, and two captures matched. That is harmless, evidence-only work,
and it is recorded here.

## Stages (each ends green on the full suite)

1. **S0b golden extension (done; see above).** Before any code change, add golden outputs for:
   - dry runs with `--volume-factor 0.98`;
   - one maximum-symmetry run on the fixture, if it finishes within 2 min;
   - `--unique-batch-size 2`;
   - smoothing modes `regenerate` and `move`;
   - smoothing output in POSCAR and LAMMPS;
   - `--report` text and stdout for dry and sparse runs.

   Record stack versions in the manifest.

   Test policy for these goldens:
   - after the change, dry goldens are compared both with no selector and
     under `--occlusion-model sparse-v715`;
   - sparse goldens are compared under the selector;
   - the only change allowed to existing tests that pass legacy arguments
     is adding the selector.
2. **S1 data.**
   - Write `validation/regenerate_cage_salt_data.py` and the generated
     `lta_cage_salt_data.py`.
   - Test: regenerating gives the same bytes, and the SHA-256s match the
     CSVs.
   - Test: `D1_BOUND` matches the values in the D1 r7 text.
3. **S2 domain.**
   - request parsing and validation;
   - window table, plus the check of the table against loaded sites;
   - charge and rebalancing, plus the brute-force oracle;
   - V_eff, plus these oracles:
     - V/4 at d = 0 for all four cages;
     - α₀ = α₁ and β₀ = β₁;
     - the scale identity;
     - Monte Carlo (10⁷ points) at d_wall within 0.5 %;
     - cold and warm cache giving identical results;
   - floors;
   - both V3 rules, plus manufactured single-violation cases;
   - streams, including seed = None;
   - record and JSON with schema_version.
4. **S3 build.** The objective for rules B and A, with finite-difference
   gradient tests; insertion; continuation and polish; relocation;
   restarts.
5. **S4 integration.**
   - sentinel semantics; the selector; rejection of legacy flags;
   - rejection of counterions without salt;
   - `finalize_cage_salt`, the assembly extension, and the final verify on
     the assembled `Structure`;
   - the cage-salt branch of the derived values and report;
   - `output_site_order` refactor, keeping the dry goldens identical;
   - sidecar and `.salt.json`; failure paths;
   - `--attempt-seed` and the smoothing-script changes;
   - the `significant_figures` floor;
   - the rejected-mode guards;
   - `resolve_occlusion_mode`, `resolve_volume_factor` at every API entry,
     the deferral and skip-validation arguments, and `assemble_structure`
     with AtomMeta;
   - the template gate in cage-salt mode;
   - atomic writes.

   Additional tests:
   - legacy and dry imports load neither the cage-salt modules nor SciPy;
   - template-gate rejection: shifted template; variant-set mismatch (all
     grouping cutoffs 0 gives 64 sites); 8R non-equidistance;
   - ion_id uniqueness;
   - window-table join: one-to-one on the fixture, failing closed with
     non-default grouping;
   - resolver precedence;
   - `write()` refusing a pending result;
   - the sidecar structure SHA-256 being checked by the verifier.

   Tests:
   - all goldens;
   - oracle 5 (step-3 snapshot); oracle 6 (determinism); oracle 7
     (precondition);
   - an independent verifier on re-parsed CIF (`CifParser(frac_tolerance=0)`,
     `primitive=False`), POSCAR and LAMMPS, using the sidecar;
   - sidecar order per format;
   - `--attempt-seed` byte reproduction;
   - the end-to-end CLI.
6. **S5 docs and packaging.** README, CHANGELOG, the module-spec notes,
   `pyproject.toml` (py-modules and SciPy), and version 7.16.0.
7. **S6 qualification (S-12).**
   - **Freeze.** Record the commit, the D2 §10 parameters and the stack in
     `qualification/v716/census-plan.json` before running.
   - **Run.** `validation/v716_s12_census.py` runs the 90 requests in the
     background with a per-request wall-clock cap of 90 min. Hitting the cap
     counts as a failure. The total budget is 12 h.
   - **Order and record (N12).** The request order is frozen in
     `census-plan.json`. All 90 requests run for each rule census
     performed: B always, A only if B fails. Each rule's pass rate and its
     Wilson interval are recorded, as D2 §9 requires.
   - **Budget.** If the 12 h budget runs out, the record states k run,
     f failed and u unrun, with unrun requests kept separate from failures.
     A decision is taken only if it is already determined (f ≥ 5, or passes
     ≥ 86). Otherwise the outcome is reported to the stakeholder as
     undetermined.
   - **Rule A.** If rule A is needed, it gets its own freeze record
     (`census-plan-A.json`) and the same budget and rules.
   - **Decide.** Apply the rule: B is retained if at most 4 fail. Otherwise
     set `COORDINATION_RULE = "A"` and run the census for A. If A also fails,
     reopen D1.
   - **Record.** `qualification/v716/census-record.*`.
   - **PDFs.** Render them if a LaTeX engine exists; otherwise record that
     they are deferred.
8. **S7 independent D4 review.**

## Acceptance

- The full suite passes.
- All goldens are identical.
- Oracles 1-7 pass.
- The S-12 decision is recorded with its census.
- The end-to-end CLI run works on the fixture.
- The independent D4 review finds no blocker.

## Non-goals

- Maximum-symmetry or unique-batch support with salt.
- Non-Al24 frameworks.
- Trivalent ions.
- A JSON input schema.
- Changes to D1 or D2; defects there are routed to their owners.
