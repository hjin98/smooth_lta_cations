# v7.15 Sparse Chloride-Occlusion Extension — D1/D2/D3 -> D4 Implementation Workplan

## Background and terminology

This workplan extends the current Al24Si24O96 LTA generator from dry Group-I/II cation substitution to sparse chloride-containing initial configurations for atomistic training.

The existing generator has one physically instantiated extra-framework cation population on grouped 4-ring (4R), 6-ring (6R), and 8-ring (8R) sites. In v7.15, two charge-accounting roles are distinguished without claiming that the roles remain spatially separable after relaxation:

- **framework-compensating cations**: the existing cation population whose formal positive charge independently compensates the 24 framework-Al charge units;
- **occlusion counterions**: additional Group-I/II cations introduced only because chloride guests add negative charge. In v7.15 these additional cations are initialized on currently supported 4R/6R/8R candidate coordinates. This is a controlled AIMD-training initialization choice, not a claim that those coordinates are the equilibrium “occlusion sites” of molten-salt zeolite A;
- **occluded chloride**: Cl- initialized at a supported alpha- or beta-cage center;
- **alpha-Cl**: a sparse realization of literature-established chloride-salt occlusion in LTA cavities;
- **beta-Cl**: an explicitly sampled trapped/configurational hypothesis for training. v7.15 must not describe beta-cage Cl as an experimentally established equilibrium LTA site.

The external molten-salt literature distinguishes framework ion-exchange behavior from occluded-site behavior and reports chloride-containing salt loading into zeolite-A cavities. The implementation must preserve that distinction in its documentation and must not elevate an initialization convention into an equilibrium-site prediction.

## 1. Outcome and authority

### Protected outcome

Generate charge-neutral, reproducible, serialization-safe Al24Si24O96 LTA initial structures containing sparse Cl- guests in alpha and/or beta cages plus the additional Group-I/II positive charge required by those guests, while preserving the complete v7.14.2 dry behavior when no occlusion option is used.

v7.15 does not implement:

- non-Al24 frameworks or other Si:Al ratios;
- dense salt loading or multiple Cl- ions in one cage;
- equilibrium guest-site prediction;
- cage-local electroneutrality;

- maximum-symmetry certification for Cl-containing structures;

## 2. Scientific and numerical contract

Let `N_i^fw` be the exact count of framework-compensating cations of supported species `i`, with formal charge `z_i`.

The existing invariant remains:

```
Q_fw = sum_i z_i N_i^fw = 24
```

Let

```
N_Cl = N_Cl^alpha + N_Cl^beta
```

and let `N_i^occ` be the exact count of added occlusion-counterion-role cations. Require independently:

```
Q_occ = sum_i z_i N_i^occ = N_Cl
```

Therefore the complete generated structure satisfies:

```
sum_i z_i (N_i^fw + N_i^occ) = 24 + N_Cl
```

The software must validate `Q_fw = 24` and `Q_occ = N_Cl` separately. Global neutrality alone is insufficient. A +23 framework population plus an excess +2 cation and one Cl- is globally neutral but invalid under v7.15.

This partition is bookkeeping/provenance for construction. It is not a claim that electrostatic compensation is uniquely separable after relaxation.

### Supported sparse chloride domain

For the canonical supported primitive LTA template:

```
0 <= N_Cl^alpha <= 2
0 <= N_Cl^beta  <= 2
N_Cl^alpha, N_Cl^beta are exact integers
```

At most one chloride is initialized per supported cage center in v7.15.

### Cage-center initialization

For the current canonical Fm-3c primitive setting, the candidate center orbits are:

```
beta:  (0,0,0), (1/2,1/2,1/2)
alpha: (1/4,1/4,1/4), (3/4,3/4,3/4)
```

These are **setting-specific initialization coordinates**. They must not be applied to an arbitrary origin/setting merely because its framework formula is Al24Si24O96.

Occlusion mode must therefore fail closed unless a new `validate_occlusion_template_setting()`-equivalent check establishes compatibility with the supported canonical template setting within a governed tolerance. At minimum the check must bind the expanded framework fractional-coordinate fingerprint, the declared/validated parent symmetry setting, and the expected two-member alpha/beta center orbits. A chemically equivalent but differently shifted/rebased template is unsupported until an explicit coordinate mapping is implemented.

When one of two equivalent cage centers is requested, choose the center maximizing the minimum periodic Cartesian distance to the final cation coordinates. Break an exact numerical tie by canonical cage ID, not by consuming the framework-population random stream. When two are requested, occupy both.

### Collision guard

After all cation placement/smoothing and final cage selection, validate every new Cl against the complete final structure using minimum-image periodic distances.

Introduce a dedicated `--occlusion-min-distance` hard lower bound with default 1.5 A. This default is only a catastrophic-overlap guard; documentation must explicitly state that it is not a species-specific equilibrium contact distance or validation of physical stability.

Reject rather than silently move an ion when the final guard fails. Users may increase the threshold for a stricter initialization policy.

### Dry-volume preservation

The existing dry model remains:

```
V_ref = (1/24) sum_i z_i N_i^fw V_i^(24)
V_target = volume_factor * V_ref
```

Only `N_i^fw` participates. Neither `N_i^occ` nor chloride contributes to the v7.15 automatic volume calculation.

This is an initialization policy chosen to preserve the established dry Li/Na/K and Group-I/II volume behavior. It is not a claim that experimental salt loading has zero volume effect. The generated report must state this limitation explicitly.

## 3. Importance and attention allocation

### Highest-value outcomes

- exact charge partition and total charge neutrality;
- zero-occlusion compatibility with v7.14.2;
- no accidental use of excess counterions in the established `/24` dry-volume interpolation;
- no false maximum-symmetry or unique-batch certification;
- deterministic, setting-safe cage placement;
- serialization of Cl in every supported format;
- preservation of metadata through the legacy smoothing path.

### Mandatory acceptance floors

- framework charge and occlusion charge validated independently;
- combined grouped-site capacity never exceeded;
- no output with a chloride collision below the hard guard;
- no occlusion request accepted for an unsupported template setting;
- no maximum-symmetry or unique-batch path silently accepts occlusion;
- all pre-existing zero-occlusion tests pass unchanged;
- generated Markdown/PDF authority/spec descendants remain source-consistent.

### Critical uncertainties

- physical adequacy of beta-cage Cl as an LTA training hypothesis;
- absence of an empirical v7.15 chloride-loading volume correction;
- absence of a validated dense-salt guest-packing model;
- exact applicability of cage-center initialization beyond the canonical template setting.

These uncertainties are handled by strict scope/labeling, not by inventing unsupported physics.

## 4. Frozen cycle decisions

### Public CLI

Add to both user-facing random entry points:

```
--alpha-cl INT
--beta-cl INT
--occlusion-n4 SPEC
--occlusion-n6 SPEC
--occlusion-n8 SPEC
--occlusion-min-distance FLOAT
```

Defaults:

```
alpha-cl = 0
beta-cl = 0
occlusion-n4/n6/n8 = empty
occlusion-min-distance = 1.5 A
```

`--occlusion-n4/6/8` means charge-balancing cations placed on currently supported grouped ring sites. The word “occlusion” denotes their charge-accounting role, not a claim that those ring coordinates are experimentally established occlusion sites.

When `N_Cl > 0`, v7.15 requires exact integer base and occlusion allocations. Reject:

- `--ratio4/6/8`;
- `--auto-rebalance`;
- `--population-mode maximum-symmetry`;
- `--unique-batch-size > 1`.

If any `--occlusion-n*` count is nonzero while `N_Cl == 0`, reject it. If `N_Cl > 0` but no exact occlusion counterion population gives `Q_occ=N_Cl`, reject it.

When `N_Cl > 0`, also reject the diagnostic `--write-candidate` path in v7.15. Its present meaning is a grouped cation candidate-variant structure and it would otherwise produce a chloride-free diagnostic artifact that could be mistaken for the requested complete occluded structure. A future explicitly labeled cage/cation candidate visualizer may reopen this restriction.

### Site capacity

For each ring family `r`:

```
sum_i (N_ri^fw + N_ri^occ) <= C_r
```

The two roles compete for the same physical grouped sites.

Place the framework population first using the existing algorithm and its existing RNG semantics. Place occlusion-counterion-role cations only on the remaining requested ring-family sites using a separately derived deterministic RNG stream. Adding occlusion must not perturb which grouped sites/variants the same seed assigns to the framework-compensating population.

### Smoothing behavior

The existing density objective remains a **cation-only** heuristic. Cl must not silently enter the Gaussian cation-density estimator.

For legacy random smoothing:

1. construct/place framework and excess cations;
2. perform existing cation smoothing over the cation population;
3. after the final cation geometry is fixed, select/place Cl cage centers;
4. perform final Cl collision validation;
5. assemble and serialize the complete structure.

Do not let repair logic drop occlusion metadata. Replace the current manual field-by-field `PopulationResult(...)` reconstruction in `generate_smooth_lta_cations_grouped.py` with a metadata-safe reconstruction such as `dataclasses.replace` plus explicit final structure/placed-ion updates, or an equivalent single authoritative builder.

### Maximum-symmetry boundary

Any nonzero occlusion input with maximum-symmetry mode must fail before MS0-MS7 optimization.

Reason: the existing certificate optimizes the grouped cation action only. Appending a cage guest afterward does not prove a maximum stabilizer for the complete structure. A future extension may add alpha/beta cage sites to the parent action and jointly optimize/certify the full structure.

### Unique-batch boundary

Any nonzero occlusion input with `--unique-batch-size > 1` must fail in v7.15.

Reason: the current canonical signature acts only on grouped cation occupations and ignores off-center variants. It is not a valid oracle for cage-guest equivalence. A future extension may define the joint action on grouped cation sites plus alpha/beta cage sites.

## 5. Data model and ownership

### PlacedIon

Extend `PlacedIon` with a role field whose backward-compatible default is framework compensation:

```
role = "framework" | "occlusion_counterion"
```

Role is provenance/bookkeeping and must not change physical species equivalence. The new field must have a default so existing keyword/positional construction paths that do not know about v7.15 remain valid where their prior API contract permits.

### Chloride object

Introduce an immutable chloride/cage record, conceptually:

```
CageSite
  cage_id
  cage_type: alpha | beta
  frac

OccludedChloride
  cage_id
  cage_type
  frac
```

Exact class/helper names remain delegated D4 space.

### PopulationResult

Avoid duplicate authoritative state where possible.

Preserve existing `alkali_counts` as the legacy **framework-compensating** count field so old volume/callers cannot silently begin seeing excess cations.

Add, with compatibility-safe empty defaults for direct constructors that previously created a dry `PopulationResult`:

```
occlusion_counterion_counts
occluded_chlorides
occlusion_allocations
```

and derived views/properties:

```
framework_cation_counts -> legacy alkali_counts
cation_counts           -> total physical cation counts
chloride_count
alpha_chloride_count
beta_chloride_count
framework_positive_charge
occlusion_positive_charge
total_positive_charge
required_total_positive_charge = 24 + chloride_count
```

Do not store mutually redundant count dictionaries unless one is explicitly retained only for compatibility and checked for consistency.

### Structure assembly

Extend the single structure-assembly boundary so the final structure is always:

```
framework atoms
+ all grouped-site cations
+ occluded chlorides
```

No secondary serializer-specific chemistry construction is permitted.

## 6. Serialization and reporting

### Species order

Retain the existing deterministic block order for every pre-existing species and append `Cl` as the final preferred species block:

```
Si Al O H Li Na K Rb Cs Fr Be Mg Ca Sr Ba Ra Cl
```

With zero Cl, serialized ordering remains identical to v7.14.2.

CIF, POSCAR/VASP, and LAMMPS `atom_style atomic` must all contain identical elemental composition. LAMMPS continues to emit no charge column.

### Population report

Report separately:

- framework-compensating composition and +24 charge;
- occlusion-counterion composition and charge;
- alpha/beta/total chloride counts;
- total formal positive charge and total formal negative charge;
- PASS of both independent charge invariants;
- each cation role and grouped site;
- each chloride cage ID/type/fractional coordinate;
- chloride minimum-distance result;
- the statement that v7.15 uses the dry framework-compensating population only for automatic volume;
- the statement that alpha/beta cage-center coordinates are initialization sites, not equilibrium-site predictions;
- the stronger warning that beta-Cl is a sampled trapped-state hypothesis.

## 8. Verification and regression matrix

### Exact positive chemistry cases

At minimum test:

```
framework +24; 1 alpha-Cl; 1 Cs+ excess
framework +24; 2 alpha-Cl; 1 Sr2+ excess
framework +24; 1 alpha-Cl + 1 beta-Cl; 1 Ba2+ excess
mixed Li/Na/K framework +24; 1 beta-Cl; 1 Rb+ excess
```

Use at least one case where framework and occlusion populations contain the same element so role bookkeeping cannot rely on species identity.

### Exact negative chemistry cases

Reject:

```
framework +23; 1 Cl; 1 Cs excess
framework +24; 1 Cl; 1 Sr excess
framework +24; 2 Cl; 1 Cs excess
framework +24; excess cation with zero Cl
framework +24; Cl with no matching excess charge
combined ring capacity overflow
alpha-Cl > 2
beta-Cl > 2
negative/noninteger chloride counts through every public numerical path
```

### Compatibility oracle

For representative legacy dry cases, with all new options omitted:

- exact structure composition unchanged;
- same framework cation grouped-site occupation for identical seed;
- same selected variants for identical seed;
- same reference/target volume;
- same report chemistry/volume values except intentional version/documentation wording;
- same serialization content modulo only intentional metadata/version text.

Prefer fixture/differential comparison against base commit behavior rather than expected values regenerated by the modified production code.

### Volume oracle

For a fixed framework-compensating composition and volume factor:

```
V_ref(no occlusion) == V_ref(with CsCl-like occlusion)
V_ref(no occlusion) == V_ref(with SrCl2-like occlusion)
```

to the existing numerical precision.

Add a counterfactual test that would fail if excess cations were accidentally included in `interpolated_dry_target_volume()`.

### Cage-setting oracle

For `tests/real_lta_primitive.cif`:

- exactly two validated alpha centers;
- exactly two validated beta centers;
- the expected alpha/beta center orbits close under the declared parent operations;
- requested one-cage placement is deterministic.

Create a deliberately shifted/rebased or fingerprint-mismatched fixture that remains chemically Al24Si24O96 but must be rejected by occlusion mode. This is the critical negative oracle against silent setting misuse.

### Smoothing oracle

- role labels/counts survive at least one accepted greedy cation move;
- final chloride placement occurs after smoothing;
- final collision guard executes on the post-smoothing structure;
- changing occlusion request must not perturb the same-seed framework-compensating cation layout before smoothing.

### Symmetry/unique guards

Assert failure for:

```
occlusion + --population-mode maximum-symmetry
occlusion + --unique-batch-size 2
```

through both executable entry points where applicable.

A test that only calls a helper below CLI dispatch cannot close these public-path claims.

### Serialization oracle

For one monovalent and one divalent occlusion case:

- CIF round trip contains exact full composition;
- POSCAR round trip contains exact full composition;
- LAMMPS data round trip contains exact full composition;
- Cl appears once in deterministic species grouping;
- LAMMPS remains `atom_style atomic` with no per-atom charge column.

### Full regression

Run `pytest -q` after all material executable edits. Existing MS0-MS7 evidence must be treated as stale for any changed shared owner until rerun. Maximum-symmetry scientific algorithms are intended to remain behaviorally unchanged; their regression still runs because shared `PopulationResult`/writer code changes.

## 11. Reopen / Challenge triggers

### D4-local blockers

- metadata loss through smoothing;
- writer/read-back loss of Cl;
- seed instability of the framework population under zero or added occlusion;
- failure to reject unsupported CLI combinations;
- collision guard not exercised at the final assembled boundary.

### D3 reopen

- supporting occlusion requires invasive duplication of the MS0-MS7 structure/certificate machinery rather than an additive random-mode path;
- one authoritative population representation cannot cleanly support both dry and sparse-occluded states.

### D2/D1 reopen or SERIOUS CHALLENGE

- evidence shows the “dry volume + explicit factor” policy is materially unsuitable for intended AIMD initialization;
- beta-Cl is to be presented as an equilibrium/experimentally established LTA state rather than a training hypothesis;
- dense salt loading or multiple guests per cage becomes required;
- noncanonical LTA settings must be accepted without a validated coordinate mapping;
- extra counterions must be modeled as free cage guests rather than controlled grouped-site initial placements;
- new literature contradicts the independent charge-partition interpretation in a way that changes intended scientific meaning.
